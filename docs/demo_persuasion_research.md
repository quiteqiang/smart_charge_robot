# 调研报告：如何用测试数据让 demo 更有说服力

> 调研日期：2026-09-16 · 方法：deep-research 多智能体调研（5 个搜索角度 → 抓取 15+ 来源 →
> 每条主张 3 票对抗验证，21 条主张通过，2 条被否决剔除）
> 目标项目：smart_charge_robot（ROS 2 矿卡自主导航 + 自动充电仿真系统，8 场景集成测试 + rosbag + RViz）

## TL;DR

有说服力的机器人 demo 不是靠"跑通一次"，而是靠**把测试证据组织成"主张 → 论证 → 证据"的结构**（UL 4600 safety case 范式），并用**重复次数 + 统计置信度 + 明确 pass/fail 准则**支撑每个主张（ISO 3691-4 / ISO 18497-4 范式）。本项目已有很好的原材料（8 场景测试、rosbag、结构化日志），差距集中在三点：**单次运行为主（缺重复+置信区间）、指标未成体系（缺 MTBF/成功率类 KPI）、证据未结构化呈现（缺 safety case 式报告与 CI 可视化**。

---

## 一、核心范式：Safety Case（安全论证）

业界（自动驾驶/AGV）证明系统可信的规范形式不是口头声明，而是 **safety case**：
一组**论证（Argument）、主张（Claim）、证据（Evidence）**，证明系统在其生命周期内不存在不合理风险 [17]。
UL 4600 把这一结构落成标准：每项安全主张必须由论证支撑，而**证据明确包括测试、分析和仿真** [10]——
这直接意味着：**本项目的 8 场景集成测试和仿真运行记录，本身就是可组织的安全证据**，缺的是结构。

UL 4600 还要求用 **SPI（安全绩效指标）** 量化论证有效性，例如"与行人保持间距的可接受违规率"、
"传感器假阴性率" [11]。西门子白皮书同样指出：L4 系统安全论证需要大规模 V&V 周期，
**物理测试与虚拟测试（仿真）的结合是行业认证趋势**，仿真测试记录可作为安全论证证据的一部分呈现 [16]。

**对本项目的落点**：把 `docs/test_report.md` 升级为 safety case 式文档——顶层主张（如
"低电量时任务不丢失"）→ 论证（状态机保存/恢复机制）→ 证据（场景 3+6 的日志、rosbag 回放、
状态转换序列）。每项主张配**可量化 KPI**（见下节），而不是只写"通过"。

## 二、指标：把"通过了"变成"N 次中成功 M 次，置信度 95%"

### 2.1 重复次数 + 置信区间是行业底线，不是可选项

- ISO 18497-4 的验收标准要求**每个测试用例至少重复 7 次**，以量化停车位置的离散度，
  并明确规定"任何位置都不得接触障碍物"的 pass/fail 准则 [1]。
- AGV 运输系统研究做仿真验收评估时，**每个实验跑 30 次重复并给出 95% 置信区间**（箱线图），
  而非报一次成功 [7]。

本项目当前测试报告是**每场景单次运行**。改成：核心场景（导航、泊靠、充电闭环）各跑 10-30 次，
报告 `成功率 = x/n`，泊靠场景附加**泊靠精度分布**（最终位姿误差，对标 ISO 3691-4 的
"量化离散度"要求 [0]）。

### 2.2 可复现、可量化的测试件与工况定义

ISO 3691-4:2023 给出了"可复现、可量化"测试证据的范本：人员检测功能用**标准化测试件**
（直径 200mm 水平圆柱体、直径 70mm 垂直圆柱体，表面反射率控制在 2%-6%），
车辆以**最大速度、≥110% 额定载荷、最坏工况**（坡道/转弯/前进/后退）驶向测试件 [0]。
关键点不是数值本身，而是方法：**明确定义测试对象、工况参数、通过准则，任何人都可复现**。

本项目的对应物：把场景 2 的"0.6m 方块障碍"参数化为**障碍尺寸/速度/注入时机的扫参矩阵**，
泊靠场景把初始位姿扰动 ±0.2m/±10° 做蒙特卡洛采样——报告"在最坏初始位姿下成功率 ≥95%"远比
"默认位姿下成功一次"有说服力。

### 2.3 指标体系模板：MTBF/MTTR + OTE

- AGV 行业标准可靠性指标是 **MTBF/MTTR**：文献故障率 λ=0.0014~0.003/h 对应 MTBF 300-700h [8]；
  中国 AGV 可靠性测评采用**定时截尾试验方案**（GJB899A 统计试验族，由 θ0/θ1/α/β/D 五个统计参数
  决定样本量与判据），可参照 GJB899A-2009、GB/T 5080.1、GB/T 29482.1、GB/T 32245 [4][5]。
  该团体标准由上海机器人产业技术研究院起草——AGV 可靠性此前**没有强制标准**，谁先按统计试验
  方案报 MTBF 谁就领先 [5]。
- OEE（可用率×性能×质量）可扩展到 AGV 运输系统，派生出 **OTE（运输综合效率）** 与
  **OFE（工厂综合效率）**，量化运输子系统对整体生产效率的影响 [6]。

**对本项目的落点**：报告里加一节"可靠性指标"：连续 N 小时不间断运行测试（记录故障注入→恢复时间，
导出 MTTR；累计无故障运行时间，给出 MTBF 下限估计）；把"充电闭环对作业效率的影响"用 OTE 式指标表达
（充电耗时占比、任务恢复率）。

## 三、仿真数据的地位：标准背书

- **PD ISO/PAS 8800**（AI 感知系统验证）：验证必须结合真实测试、**仿真和统计评估**，
  显式定义输入空间（距离、速度、光照、噪声/扰动），用带真值的测试用例、pass/fail 判据和
  定量性能目标执行 V&V，并**明确将场景回放（scenario replay）列为方法** [2]。
- **PD ISO/IEC TR 5469 / IEC TS 62998-1**：虚拟测试（MIL/SIL/HIL）被强烈推荐为真实测试的
  根本补充；仿真环境可系统记录每个测试用例的全部元数据，生成**可复现数据集**，支持
  统计意义上的性能和置信度分析 [3]。

这回答了"仿真 demo 的数据算不算数"：**算，且标准鼓励用场景回放+统计指标作为证据**。
本项目应充分利用已有的确定性仿真优势——每个测试用例的世界状态、注入事件、真值轨迹都可完整记录
（rosbag 已在录），把"可复现数据集"作为正式卖点写进报告。

## 四、演示与回放工具链

**Foxglove** 提供 ROS 2 数据可视化的两条路径：Foxglove Bridge 实时可视化运行中的机器人栈，
或回放录制的 `.mcap` 文件 [9]。对 demo 场景的价值：
- 投资人/客户面前：不用起完整 ROS 环境，直接回放录好的 mcap（demo 稳定性从"祈祷别 crash"变为 100% 可控）；
- 评审场景：同一 rosbag 可暂停/快进/逐帧检查泊靠过程，比 RViz 实时演示更有"可审计"感；
- 与 safety case 报告交叉引用：报告里每个场景配"回放此 bag 复现"链接。

## 五、开源可信度信号（面向 GitHub 观众）

机器人开源项目的 README 专业信号清单（来自 Fast-DDS、Pinocchio 等头部项目的实证）：
License 徽章、文档状态徽章、版本/下载徽章、**跨平台 CI 状态徽章（夜间构建）**、
**pre-commit CI 状态**、**测试覆盖率徽章** [12][13][14]；跨 ROS 2 发行版部署状态矩阵
（Humble/Jazzy/Kilted/Rolling）[15]。

本项目当前 README 已不错（双语、Docker 一键、测试说明），差：
- CI badge（接上 GitHub Actions 后一行 markdown）；
- 测试通过率/覆盖率徽章；
- **演示视频/GIF**（RViz 录屏 60-90 秒，放 README 顶部——对机器人项目这是性价比最高的说服力资产）；
- 把 `docs/test_report.md` 的关键数字（8/8 场景、395s、1.9GB 内存跑通）做成 README 表格。

## 六、分层指标框架的组织方式

Plus 为 L4 系统建立了**分层指标框架**：在系统级和子系统级定义、跟踪 KPI，
生成"客观且可审计的证据"支撑核心安全主张 [18]。本项目可直接映射：

| 层级 | 主张 (Claim) | KPI (SPI) | 现有证据 | 缺口 |
|---|---|---|---|---|
| 系统 | 低电量任务不丢失 | 任务恢复率 = 恢复数/中断数 | 场景 3+6 | 需 N 次重复 |
| 系统 | 自动充电闭环可靠 | 充电闭环成功率、端到端耗时分布 | 场景 3-6 | 需重复+置信区间 |
| 子系统 | 泊靠精度达标 | 泊靠位姿误差分布 (x, y, yaw) | 场景 4 | 需真值对比+蒙特卡洛初始位姿 |
| 子系统 | 避障安全 | 最小障碍间距分布 | 场景 2 | 需扫参（障碍尺寸/时机） |
| 子系统 | 异常进入安全态 | 进入 ERROR 的正确率、人工恢复时间 (MTTR) | 场景 7 | 需故障注入矩阵 |
| 可靠性 | 长时间稳定运行 | 无故障连续运行时长、MTBF 下限 | 无 | 需 24h+ soak 测试 |

## 七、行动清单（按性价比排序）

1. **测试报告加统计**：核心场景（3/4/5/6）各重复 10-30 次，报成功率 + 泊靠精度分布 + 95% CI
   （工具：`tests/test_integration.py` 包一层循环 + matplotlib 箱线图，1-2 天）；
2. **Safety case 式重排 test_report.md**：主张→论证→证据三段式，每主张挂 KPI 与 rosbag 链接（0.5 天）；
3. **泊靠蒙特卡洛**：初始位姿扰动采样 20-50 组，报成功率与最坏情况（0.5 天，纯仿真算力换说服力）；
4. **soak 测试**：连续运行 12-24h 随机任务+随机低电量注入，记录故障与恢复（过夜跑，0 人力）；
5. **Foxglove/Web 回放链**：把录制 bag 放 release/网盘，README 放回放指引（0.5 天）；
6. **README 徽章 + 演示视频**：CI badge + 60s RViz 录屏 GIF（1 天）；
7. （中期）按 ISO 3691-4 思路补"测试件标准化"文档：障碍/测试件的尺寸、反射率、工况参数表，
   让任何人可复现你的场景。

## 八、被验证流程否决的说法（避免采信）

调研中以下流行说法经 3 票对抗验证被**否决**，写报告/做 PPT 时不要用：
- ~~"某 AGV 厂商博客写的 SAT 阈值（对接成功率 ≥99% 等）是行业通用验收标准"~~ ——
  单一厂商营销博客，非行业标准，NTSB 官员评价此类自愿安全报告"有些是营销手册"；
- ~~"头部 AV 公司（Cruise/Waymo/Argo）的公开安全报告是行业公认的安全论证证据形式"~~ ——
  白皮书仅"概述"这些公司做法，且 Argo 已倒闭、Uber ATG 已出售，作为范式引用已过时。
